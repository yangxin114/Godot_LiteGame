# 项目上下文与 AI 代码生成 / 审查 指南（简明）

目的：为 AI（包括自动代码生成、回答编码问题与代码审查）提供本项目的上下文约束与编码指导，确保产出与现有代码库风格、性能与可维护性一致。

## 项目上下文（必读）
- 引擎：Godot（优先 4.6 API）。任何生成代码应以 Godot 4.6 的 API 和类型注解为准，不允许使用Godot 3.x独有的代码。
- 目录约定（本项目常用）：
  - res://scenes/ — 场景文件（.tscn）
  - res://scripts/ — GDScript（.gd）
  - res://assets/ — 资源（图片、音频）
  - res://ui/ — UI 场景/控件
- 主场景与输入映射：保持 Project Settings 中 Main Scene 与 Input Map 不变，除非用户明确要求修改。
- 会话必须使用中文回复

## 代码风格与约定
- 语言：使用 C# 语言，不适用GDScript。
- 命名：snake_case 用于文件/变量，PascalCase 用于场景/资源名和类名。
- 类型注解：尽量添加.NET 类型注解（如 int, float, string, bool, List<T> 等）。
- 注释：注释必须使用中文。所有类都需要有注释。函数顶端写简短描述与参数说明；复杂逻辑需内联注释。
- 优先使用项目res://scripts/ 目录下已有的工具类与方法，避免重复造轮子。
- 日志：优先使用项目中已有的日志系统（如 Logger2）进行日志记录。且日志记录都使用英文。

## 设计与实现原则
- 最小侵入：修改应局限于指定文件，避免不必要的大规模重构；重大改动先提出方案并征求确认。
- 向后兼容：在可能的情况下保持现有行为（功能/输入/输出）不变，除非用户要求破坏性更改。
- 性能与内存：避免在 _process(delta) 中做昂贵操作；使用对象池与预加载（preload）管理资源。
- 资源管理：使用 res:// 路径引用资源，避免绝对路径；大量纹理/音频需注明压缩建议。

## 回答与审查行为
- 不确定时先提问：当需求不明确或影响边界不清，先列出可选方案并询问用户偏好。
- 给出最小可运行更改：生成补丁/代码时优先给出最小可运行示例并指出需放置的文件路径。
- 说明变更影响：每次建议附带简短影响说明（兼容性、性能、测试需求）。
- 安全与许可：不引入受限/不兼容许可的第三方库，注明任何新依赖与安装步骤。

## 提交与审查清单（每次变更）
- [ ] 保持或更新主场景运行行为
- [ ] 类型注解与注释齐全
- [ ] 无明显性能问题（长循环/每帧分配）
- [ ] 使用 res:// 路径引用资源
- [ ] 提供测试或手动验证步骤
- [ ] 变更说明与回滚建议
